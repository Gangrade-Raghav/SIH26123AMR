## 1. Current Dashboard Architecture

The current dashboard is implemented as a self-contained, zero-dependency Python web application embedded inside `scripts/fleet_dashboard.py`:

- **Backend Runtime**: Python 3.12, ROS 2 Jazzy client library (`rclpy`), standard library `http.server.BaseHTTPRequestHandler` and `socketserver.ThreadingTCPServer`.
- **Node Architecture**: `FleetMonitorNode` inherits from `rclpy.node.Node`, subscribing directly to active ROS 2 graph topics:
  - `/clock`: Simulation time and real-time factor (RTF).
  - `/tasks/all`: Active task pool, lifecycle status, pickup/dropoff poses, and assignments.
  - `/tasks/events`: Task lifecycle state transitions and execution events.
  - `/fleet/cbba_bids`: Multi-agent CBBA bid broadcasts and auction allocations.
  - `/fleet/reservations`: Space-time cell reservation broadcasts.
  - `/fleet/conflicts`: Vertex and edge-swap conflict detection reports.
  - `/fleet/deadlocks`: WFG cycle detection events and recovery actions.
  - `/fleet/coordination_status`: Real-time yield/wait coordination status per AMR.
  - `/fleet/comm_profile`: Active communication degradation profile and impairment parameters.
  - `/fleet/comm_metrics`: Fleet-wide packet delivery, drop rates, latency, and jitter.
  - Per-robot topics (`amr_0` .. `amr_9`): `/{r_id}/odom` (pose, speed, odometry), `/{r_id}/scan` (LiDAR health, obstacle clearance), `/{r_id}/bundle` (CBBA allocated tasks and convergence state), `/{r_id}/rolling_plan` (horizon and execution paths, replan counts, latency).
- **REST Endpoints**:
  - `GET /`: Serves static embedded `DASHBOARD_HTML` containing HTML5, CSS3, and JavaScript.
  - `GET /api/state`: Returns RFC 8259-compliant JSON generated by `FleetMonitorNode.get_fleet_summary()`.
  - `POST /api/task/create`: Translates JSON payload to a ROS 2 service call on `/tasks/create` (`CreateTask.srv`) and returns acceptance status.
  - `POST /api/task/control`: Translates JSON payload to a ROS 2 service call on `/tasks/control` (`ControlTask.srv`) for `CANCEL` or `REQUEUE` actions.
- **Frontend Architecture**:
  - Pure HTML/CSS/JavaScript with zero external dependencies (no Node.js, npm, React, Vue, or external CDN requirements).
  - Polling loop via `setInterval(pollState, 500)` fetching `/api/state` and performing targeted DOM mutations and HTML5 2D Canvas rendering.

## 2. Current Components

1. **Header Bar**: Top bar displaying title, simulation time (`sim_time_sec`), real-time factor (`RTF`), host CPU/RAM utilization, and a `+ CREATE TASK` button.
2. **2D Warehouse Spatial Radar Canvas**: HTML5 canvas rendering perimeter walls, grid lines, aisle dashed centerlines, storage racks, pickup bays, dropoff hubs, and robot circles with heading needles and A* trajectory paths.
3. **AMR Telemetry Matrix**: CSS grid displaying robot cards with key-value rows for pose, plan, horizon, speed, heading, odometry, and LiDAR rate.
4. **CBBA Consensus Allocator**: Status callout banner (`CONVERGED` / `NEGOTIATING`), bids count, estimated makespan, protocol name, and bundle chips.
5. **Task Lifecycle & Dispatch Registry**: Mini metric counters (`TOTAL`, `ASSIGNED`, `PENDING`, `COMPLETED`), 7-column HTML table of tasks, and action buttons (`Cancel`, `Requeue`).
6. **CBBA Bid Inspector**: Sub-card showing multi-robot bid scorecards for a selected task with a `★ WINNER` badge.
7. **Multi-Agent Coordination & Safety (M6)**: Metric rows for space-time reservations, conflicts, WFG deadlocks, and minimum observed distance.
8. **Communication Degradation (M7)**: Metric rows for active profile, loss rate, latency, packet drop counters, and stale message counts.
9. **Operator Task Dispatch Modal**: Modal popup for task injection with AUTO vs DIRECT strategy.

## 3. Existing Data Sources

All dashboard information originates from ground-truth ROS 2 topics, Linux system files, and workspace configuration files:

| Telemetry Field | Source Topic / Origin | Data Type | Description |
| :--- | :--- | :--- | :--- |
| **Clock & RTF** | `/clock` | `rosgraph_msgs/msg/Clock` | Simulation timestamp & real-time factor calculation |
| **Fleet Poses & Kinematics** | `/{r_id}/odom` | `nav_msgs/msg/Odometry` | $(x, y, \theta)$, $v$, $\omega$, cumulative distance traveled |
| **Obstacle & LiDAR Health** | `/{r_id}/scan` | `sensor_msgs/msg/LaserScan` | Min obstacle range, LiDAR update frequency (Hz) |
| **Rolling Horizon Paths** | `/{r_id}/rolling_plan` | `amr_fleet_msgs/msg/RollingHorizonPlan` | Horizon steps ($h$), execution window ($w$), $(x, y)$ path arrays |
| **Decentralized Bundles** | `/{r_id}/bundle` | `amr_fleet_msgs/msg/RobotBundle` | Committed task list per AMR, convergence flag |
| **Task Registry & Lifecycle** | `/tasks/all` | `amr_fleet_msgs/msg/TaskList` | Task IDs, pickup/dropoff poses, priority, status, assigned AMR |
| **Task State Transitions** | `/tasks/events` | `amr_fleet_msgs/msg/TaskEvent` | Event types, transitions, timestamps, error details |
| **CBBA Bids & Consensus** | `/fleet/cbba_bids` | `amr_fleet_msgs/msg/CBBABid` | Bid values per task per AMR, winning allocations |
| **Space-Time Reservations** | `/fleet/reservations` | `amr_fleet_msgs/msg/SpaceTimeReservation` | Active reservations, cell coordinates, time steps |
| **Coordination Conflicts** | `/fleet/conflicts` | `amr_fleet_msgs/msg/ConflictReport` | Vertex and edge-swap conflict detections |
| **Deadlock Events** | `/fleet/deadlocks` | `amr_fleet_msgs/msg/DeadlockEvent` | WFG cycles detected, recovery actions, durations |
| **Coordination Status** | `/fleet/coordination_status` | `amr_fleet_msgs/msg/CoordinationStatus` | Per-robot yield/wait status, target cells |
| **Comm Profile & Impairment**| `/fleet/comm_profile` | `amr_fleet_msgs/msg/CommunicationProfile` | Profile name, latency ms, loss probability |
| **Comm Transport Metrics** | `/fleet/comm_metrics` | `amr_fleet_msgs/msg/CommunicationMetrics` | Delivered, dropped, stale, expired counts |
| **Host Compute Telemetry** | `/proc/stat`, `/proc/meminfo` | Linux `/proc` filesystem | Host CPU % and RAM used/total MB |
| **Warehouse Topology** | `config/maps/*.yaml` | YAML configuration files | Dimensions, rack geometry, stations, charging bays |

## 4. Components to Retain

Every existing capability and data point will be strictly preserved:
1. **Full Ground-Truth Fleet Telemetry**: Robot positions, headings, velocities, odometry, sensor rates, and laser obstacle distances.
2. **M3 Task Lifecycle Control**: Task creation (`/tasks/create`), cancellation (`CANCEL`), and requeuing (`REQUEUE`).
3. **Decentralized CBBA Auction Logic**: Exchanged bids, winning allocations, bundle assignments, and convergence state.
4. **M5 Rolling-Horizon Navigation**: Current execution path ($w$), planning horizon path ($h$), replan counts, and planning latency.
5. **M6 Coordination & Deadlock Recovery**: Space-time reservations, conflict reports, WFG cycle reports, and yield states.
6. **M7 Communication Resilience**: Packet metrics, drop rates, latency, jitter, and active impairment profiles.
7. **REST Endpoints & Python Architecture**: Exact compatibility with `/api/state`, `/api/task/create`, `/api/task/control`.

## 5. Components to Redesign

1. **Overall Page Structure**:
   - Transition from 2-column layout to a 4-zone industrial command center:
     - **Top**: Compact Header with key metric blocks and status badges.
     - **Middle-Left**: Dedicated, filterable **Communication Log** stream.
     - **Middle-Center**: Dominant **Warehouse Map** with zoom/search controls, architectural rendering, and pinned robot callouts.
     - **Middle-Right**: Vertical **Robot Tasks** list with compact robot cards, state badges, battery/task progress bars, and state summary.
     - **Bottom**: Full-width **Task Queue** workspace with status tabs, card/table views, completion summary, and `+ Add Task` modal trigger.
2. **Visual Design System & Palette**:
   - Deep navy / charcoal foundation frame (`#090d16` / `#000000`).
   - Clean, light industrial card surfaces (`#ffffff` / `#f8fafc`) with subtle borders (`#e2e8f0` / `#cbd5e1`).
   - NRDAS Orange (`#ff7a00`) as the primary action and accent color.
   - Restrained, standardized status colors:
     - Green (`#10b981`) = MOVING / ONLINE / HEALTHY
     - Blue (`#0284c7`) = CHARGING / ACK / SYSTEM
     - Orange/Yellow (`#ff7a00` / `#f59e0b`) = PICKING / ACTIVE / BUSY
     - Red (`#ef4444`) = CONFLICT / ERROR / ALERT / STOPPED
     - Gray (`#64748b`) = IDLE / INACTIVE
3. **Communication Stream (Left Panel)**:
   - Real event logging stream tracking actual ROS 2 events (task state transitions, CBBA bid submissions, coordination yields, deadlock alerts, comm profile changes).
   - Filter buttons: `ALL`, `AMR-01` through `AMR-10`, `SYSTEM`.
   - Event tags: `[CBBA]`, `[TASK]`, `[PLAN]`, `[SAFETY]`, `[COMM]`, `[SYSTEM]`, `[ALERT]`, `[QUERY]`, `[ACK]`, `[BUSY]`.
4. **Interactive Map Canvas (Center Panel)**:
   - Architectural rendering on off-white grid floor.
   - Pinned robot information badges (`AMR-01 MOVING 78%`, etc.) tracking robot positions dynamically.
   - Top-right controls: `Search`, `Zoom (-) / 100% / (+)`, `2D / 3D` toggle.
   - Visual legend for `Current Path` (solid orange), `Planned Path` (dashed), `Alternative Path` (dotted), racks, zones, and charging stations.
5. **Robot Task Cards (Right Panel)**:
   - Cards showing AMR ID, status dot (`MOVING`, `PICKING`, `CHARGING`, `IDLE`), battery progress bar, active task details (`Pick -> Deliver`), task completion progress bar, and 3D isometric robot glyph.
   - Bottom `ROBOT STATES` tally (`Moving: N`, `Picking: N`, `Charging: N`, `Idle: N`, `Error: N`).
6. **Task Queue Workspace (Bottom Panel)**:
   - Category tabs: `AVAILABLE (N)`, `ASSIGNED (N)`, `IN PROGRESS (N)`, `COMPLETED (N)`.
   - Card view showcasing task cards with priority badges (`High`, `Medium`, `Low`), locations (`A1 -> Dock 2`), and direct `[Assign]` / `[Cancel]` / `[Requeue]` buttons.
   - "COMPLETED (TODAY)" summary widget with progress bar and completion percentage.
   - Detailed table view and slide-out / inline **CBBA Bid Inspector** displaying full multi-robot bid scorecards.

## 7. Proposed Visual System

### 7.1 Color Palette
- **Canvas Base Foundation**: `#0b0f19` (Deep obsidian/charcoal framing)
- **Panel Surface Cards**: `#ffffff` (Primary clean technical surface), with light gray sub-cards `#f8fafc` and `#f1f5f9`
- **Panel Borders**: `#e2e8f0` (1px clean technical stroke)
- **NRDAS Brand Accent**: `#ff7a00` (Vibrant NRDAS industrial orange)
- **Accent Hover / Active**: `#e06c00` / `#ff8c1a`
- **Status Accents**:
  - `MOVING / ONLINE / SUCCESS`: `#10b981` (Emerald)
  - `CHARGING / SYSTEM / ACK`: `#0284c7` (Sky/Cobalt)
  - `PICKING / ACTIVE / BUSY`: `#ff7a00` / `#f59e0b` (Orange/Amber)
  - `WARNING / DEGRADED`: `#eab308` (Yellow)
  - `ERROR / CONFLICT / ALERT`: `#ef4444` (Crimson)
  - `IDLE / UNASSIGNED`: `#64748b` (Slate)

### 7.2 Typography
- **Primary Technical Font**: `'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif`
- **Data & Telemetry Font**: `'JetBrains Mono', 'Fira Code', 'Roboto Mono', monospace`
- **Scale**:
  - Brand Header: `16px`, bold uppercase, letter spacing `0.8px`
  - Section Headers: `12px`, bold uppercase, letter spacing `0.6px`
  - Metrics Values: `18px - 22px`, tabular bold
  - Metric Labels: `10px`, uppercase, medium weight
  - Body / Feed Text: `11px - 12px`, normal weight
  - Tags & Badges: `9px - 10px`, bold uppercase

### 7.3 Micro-Interactions & Controls
- Active state highlighting (orange background with high contrast text on active tab/log row).
- Subtle hover elevation (`translateY(-1px)`) and border glow on cards and interactive buttons.
- Tactile buttons with 6px border-radius and crisp borders.
- Interactive modal with smooth fade/scale animation and form validation.

## 8. Responsive Behavior

- **Desktop (>1280px)**: Standard 3-column middle section (`22% Communication Log | 52% Warehouse Map | 26% Robot Tasks`) over full-width Task Queue.
- **Tablet (900px - 1280px)**:
  - Header metric blocks wrap into 2 rows.
  - Middle section collapses into 2 rows: Top: Full-width Warehouse Map; Bottom: Side-by-side Communication Log (50%) and Robot Tasks (50%).
  - Bottom Task Queue scrolls horizontally or stacks cards.
- **Mobile (<900px)**:
  - Single column stack: Header -> Warehouse Map -> Robot Tasks -> Task Queue -> Communication Log.
