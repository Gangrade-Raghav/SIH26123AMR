## 1. Executive Summary & Review Intent

This checkpoint provides complete architectural, algorithmic, and empirical evidence for **Milestone M5: Rolling-Horizon Task Planning**.

Milestone M5 bridges the gap between decentralized task allocation (Milestone M4, CBBA) and physical robot execution. While M4 answers *"Which robot gets which tasks?"*, M5 answers:
> *"Given my assigned tasks, what should I execute next, and what route/schedule should I request over the planning horizon ($h$) and execution window ($w$)?"*

### Core Verified Capabilities:
1. **Rolling-Horizon Planning Architecture**: Implementation of the RHCR core engine with lookahead planning horizon $h=10$ steps ($5.0\,\text{m}$) and execution window $w=4$ steps ($2.0\,\text{m}$).
2. **Sub-Goal Lifecycle State Machine**: Autonomous decomposition of assigned transport tasks into ordered spatial sub-goals (`IDLE` $\rightarrow$ `TRANSIT_TO_PICKUP` $\rightarrow$ `TRANSIT_TO_DROPOFF` $\rightarrow$ `NEXT_TASK` $\rightarrow$ `ALL_COMPLETED`), with lifecycle event emission to M3 Task Manager (`/tasks/update_status`).
3. **Task Sequencing Heuristics**: Four modular ordering heuristics (`PRIORITY_FIRST`, `SHORTEST_PATH_FIRST`, `DEADLINE_FIRST`, `BUNDLE_ORDER`) strictly enforcing **100% bundle preservation** (zero dropped, duplicated, or unassigned tasks).
4. **Deterministic Single-Agent A* Pathfinding**: Collision-free 4-connected grid pathfinding on the $0.5\,\text{m}$ discretized warehouse world, featuring deterministic tie-breaking and sub-millisecond execution ($0.09\,\text{ms}$ average latency).
5. **Deterministic Replanning Triggers**: Replanning occurs strictly upon sub-goal arrival ($d \le 0.5\,\text{m}$), execution window exhaustion ($\text{steps} \ge w$), bundle change, or empty path.
6. **Real ROS 2 + Gazebo Harmonic Fleet Demonstration**: Live execution across 5 AMRs in Gazebo Harmonic with active CBBA bundles, generating 37 valid planning cycles, driving physical motion in simulation ($4.23\,\text{m}$ to $4.86\,\text{m}$ displacement per AMR), and streaming telemetry.

## 3. Technical Implementation Details

### 3.1. ROS 2 Message Interfaces (`amr_fleet_msgs`)
Three explicit ROS 2 message definitions were created, compiled, and verified:
1. `PlanningRequest.msg`: Standardized abstraction for route requests specifying start pose, goal pose, horizon steps ($h$), execution window ($w$), task ID, and sub-goal type.
2. `PlanningResponse.msg`: Standardized planning response containing full path, truncated horizon path, execution window path, total path cost, planning latency, and replan counter.
3. `RollingHorizonPlan.msg`: Comprehensive telemetry message published per AMR on `/{robot_id}/rolling_plan` streaming assigned bundle, ordered task queue, current phase, target waypoint, horizon trajectory, and validity status.

### 3.2. Warehouse Grid Discretization (`amr_fleet_sim`)
The `GridWorld` class was extended with:
- Metric-to-grid coordinate transforms: `to_grid(x, y)` and `to_world(gx, gy)`.
- Dynamic obstacle operations: `add_obstacle(pos)` and `remove_obstacle(pos)`.
- Factory constructor `create_warehouse_grid(resolution=0.5, warehouse_size=16.0)` representing perimeter walls and interior shelving racks matching the Gazebo simulation environment.

### 3.3. Core Algorithmic Planning Engine (`amr_fleet_core`)
Implemented in `src/amr_fleet_core/amr_fleet_core/rh_planner.py`:
- **`SingleAgentAStar`**: Deterministic 4-connected grid A* pathfinder. Admissible Manhattan distance heuristic with deterministic lexicographical tie-breaking $(f, h, \text{counter}, \text{pos})$ guaranteeing bitwise identical trajectories.
- **`TaskSequencer`**: Modular task sequencing engine:
  - `PRIORITY_FIRST`: Sorts by $(- \text{priority}, \, \text{pickup\_distance}, \, \text{task\_id})$.
  - `SHORTEST_PATH_FIRST`: Greedy nearest-neighbor TSP routing.
  - `DEADLINE_FIRST`: Earliest deadline first (EDF).
  - `BUNDLE_ORDER`: Retains CBBA insertion order.
  - **Bundle Preservation**: Validates that $100\%$ of assigned bundle tasks are retained without additions or drops.
- **`RollingHorizonPlanner`**:
  - Maintains state machine: `IDLE`, `TRANSIT_TO_PICKUP`, `TRANSIT_TO_DROPOFF`.
  - Computes complete collision-free path, truncates to horizon $h$, extracts execution window $w$.
  - Evaluates deterministic replan conditions: sub-goal arrival ($d \le 0.5\,\text{m}$), execution window exhaustion ($\text{steps} \ge w$), and bundle mutations.

### 3.4. Decentralized ROS 2 Planning Node (`rh_node`)
Implemented in `src/amr_fleet_core/amr_fleet_core/rh_node.py`:
- Runs independently per AMR in isolated namespaces (`/amr_0` to `/amr_4`).
- Handles differential drive odometry frame alignment using initial spawn offsets (`spawn_x`, `spawn_y`):
  $$x_{\text{world}} = x_{\text{spawn}} + x_{\text{odom}}, \quad y_{\text{world}} = y_{\text{spawn}} + y_{\text{odom}}$$
- Asynchronous task caching: safely handles asynchronous arrival of `/tasks/all` and `/{robot_id}/bundle`.
- Publishes task lifecycle events to `/tasks/update_status` (`IN_PROGRESS` on pickup arrival, `COMPLETED` on dropoff delivery).
- Publishes smooth velocity commands (`cmd_vel`) to track waypoints within the active execution window.

### 3.5. Industrial Brutalist Dashboard (`fleet_dashboard.py`)
- Live web server on port 8080 styled in Industrial Brutalist design (Palette: Industrial Orange `#FF5500`, Dark Slate `#1A1D20`, Pure White `#FFFFFF`, Pure Black `#0A0C0E`).
- Real-time 2D Canvas rendering of rolling-horizon paths (dashed orange line) and execution windows (solid white trajectory) with sub-goal target markers.
- Table displaying each robot's active task ID, sub-goal phase, replan count, planning latency, and validity indicator.
