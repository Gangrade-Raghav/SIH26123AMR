### 3.2. Domain Model & Lifecycle State Machine (`src/amr_fleet_core`)

Located in `src/amr_fleet_core/amr_fleet_core/task_model.py`:

- **`TaskPriority(IntEnum)`**:
  - `LOW = 1`, `NORMAL = 2`, `HIGH = 3`, `CRITICAL = 4`
  - Includes robust string and integer coercion (`TaskPriority.from_str('HIGH')`).
- **`TaskLifecycleState(Enum)`**:
  - `PENDING`: Initial state upon creation; eligible for allocation bidding.
  - `ASSIGNED`: Formally allocated to a specific robot agent.
  - `IN_PROGRESS`: Executing agent has initiated motion toward pickup/dropoff.
  - `COMPLETED`: Delivery verified at dropoff location (**Terminal**).
  - `FAILED`: Aborted due to unrecoverable condition or timeout (**Terminal**).
  - `CANCELLED`: Externally revoked or superseded (**Terminal**).
- **Enforced State Transition Matrix**:
  ```
  PENDING     ---> ASSIGNED, CANCELLED
  ASSIGNED    ---> IN_PROGRESS, PENDING (preemption/release), FAILED, CANCELLED
  IN_PROGRESS ---> COMPLETED, FAILED, CANCELLED
  COMPLETED   ---> [Terminal - No further transitions]
  FAILED      ---> [Terminal - No further transitions]
  CANCELLED   ---> [Terminal - No further transitions]
  ```
  Attempting any invalid or skipped transition (e.g. `PENDING -> COMPLETED` or transition out of `COMPLETED`) immediately raises `InvalidTaskTransitionError`.
- **Truthful Duration & Temporal Metrics**:
  - `waiting_time`: $\Delta t$ between `created_at` and execution start (`started_at` or `assigned_at`). Returns `None` if unassigned.
  - `execution_time`: $\Delta t$ between `started_at` and terminal resolution (`completed_at`, `failed_at`, `cancelled_at`). Returns `None` if not completed.
  - `total_duration`: $\Delta t$ between `created_at` and terminal resolution.
  - `deadline_slack`: $\text{deadline} - \text{completed_at}$ (positive = on-time with slack, negative = tardy).

## 4. Deterministic Task Generator

Located in `src/amr_fleet_core/amr_fleet_core/task_generator.py`:

- **PRNG Isolation**: Encapsulates an isolated `random.Random(seed)` instance to prevent global PRNG contamination and guarantee identical task sets across runs.
- **Generation Modes**:
  1. `STATION_PAIR` (default): Samples pickup locations from discrete warehouse pickup pads (`(2,2)`, `(2,13)`, `(13,2)`, `(13,13)`) and dropoff locations from the central hub (`(7,7)`, `(7,8)`, `(8,7)`, `(8,8)`).
  2. `BOUNDED_RANDOM`: Rejection-samples continuous 2D coordinates within the warehouse boundary ($0.5 \le x, y \le 15.5$), enforces minimum Euclidean travel distance ($d \ge 1.5\,\text{m}$), and rejects points intersecting storage rack obstacle boxes.
- **Priority & Deadline Modeling**:
  - Configurable priority distribution weights (`LOW: 0.15`, `NORMAL: 0.55`, `HIGH: 0.20`, `CRITICAL: 0.10`).
  - Configurable deadline window $(\Delta t_{\min}, \Delta t_{\max})$ relative to task creation time.

## 6. ROS 2 Task Manager Node & Topic Interfaces

Located in `src/amr_fleet_core/amr_fleet_core/task_manager_node.py` (executable: `ros2 run amr_fleet_core task_manager`):

- **`/tasks/all` (`amr_fleet_msgs/TaskList`)**: Periodic publication ($1.0\text{--}5.0\,\text{Hz}$) of the entire task registry with live statuses and assigned robot IDs.
- **`/tasks/available` (`amr_fleet_msgs/TaskList`)**: Dynamic view containing strictly `PENDING` tasks eligible for allocation bidding.
- **`/tasks/events` (`amr_fleet_msgs/TaskEvent`)**: Event stream publishing confirmed state transitions, actor robot IDs, and transition rationale.
- **`/tasks/update_status` (`amr_fleet_msgs/TaskEvent`)**: Inbound subscription interface allowing robot agents or coordinators to request lifecycle transitions (`ASSIGNED`, `IN_PROGRESS`, `COMPLETED`, `FAILED`, `CANCELLED`). Transitions are validated against the state machine before committing.
