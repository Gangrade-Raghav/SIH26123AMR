### Claim 5: Mathematical Formulation & Diminishing Marginal Utility (DMU)

#### 5.1. Formal Definition of DMU
In the foundational CBBA formulation (Choi, Brunet, How, IEEE Trans. Robotics, 2009), the marginal utility $c_{ij}(p_i)$ of adding task $j$ to path $p_i$ satisfies **Diminishing Marginal Utility (DMU)** if and only if:
$$c_{ij}(p_i \oplus \{k\}) \le c_{ij}(p_i), \quad orall j 
otin p_i, \; k 
otin p_i$$
That is, extending an agent's path with additional tasks cannot increase the marginal score of any unassigned task. DMU is the foundational property that guarantees finite convergence and eliminates cyclic outbidding loops.

#### 5.2. Implementation Formulation
In `amr_fleet_core/cbba_agent.py`, the score for task $j$ appended to path $p_i$ is computed as:
$$S_i(j \mid p_i) = w_p \cdot 	ext{priority}_j - w_d \cdot D_i(j \mid p_i) - 	ext{penalty}_i(j)$$
where:
- $w_p = 100.0$ (priority weight)
- $w_d = 2.0$ (distance discount factor)
- $D_i(j \mid p_i)$ is the **cumulative route distance** along the entire trajectory starting from robot position $\mathbf{x}_i$, traversing all intermediate tasks in path $p_i$, to the pickup and dropoff of task $j$:
  $$D_i(j \mid p_i) = 	ext{dist}(\mathbf{x}_i, 	ext{pickup}_{p_i[0]}) + \sum_{m=0}^{|p_i|-1} \Big(	ext{dist}(	ext{pickup}_{p_i[m]}, 	ext{dropoff}_{p_i[m]}) + 	ext{dist}(	ext{dropoff}_{p_i[m]}, 	ext{pickup}_{p_i[m+1]})\Big) + 	ext{dist}(	ext{dropoff}_{p_i[-1]}, 	ext{pickup}_j) + 	ext{dist}(	ext{pickup}_j, 	ext{dropoff}_j)$$

#### 5.3. Proof of DMU Compliance
In 2D metric Euclidean space, path distances satisfy the triangle inequality:
$$	ext{dist}(A, C) \le 	ext{dist}(A, B) + 	ext{dist}(B, C)$$
When an intermediate task $k$ is added to path $p_i$ before task $j$, the detour to visit task $k$'s pickup and dropoff strictly increases the cumulative route distance to reach task $j$:
$$D_i(j \mid p_i \oplus \{k\}) \ge D_i(j \mid p_i)$$
Because $w_d > 0$ and priority is static:
$$S_i(j \mid p_i \oplus \{k\}) \le S_i(j \mid p_i)$$
Furthermore, any lateness penalty $	ext{penalty}_i(j)$ is non-decreasing with elapsed trajectory time.
Therefore:
$$c_{ij}(p_i \oplus \{k\}) \le c_{ij}(p_i)$$
**Conclusion**: The implemented marginal utility function **strictly and genuinely satisfies Diminishing Marginal Utility (DMU)** under metric space assumptions. It is not an ad-hoc heuristic.

### Claim 6: Asynchronous ROS 2 Execution, Timestamps, and Tie-Breaking

#### 6.1. Asynchronous Gossip & Network Delays
In a distributed ROS 2 network, broadcast messages on `/fleet/cbba_bids` arrive asynchronously with variable latency. The CBBA consensus phase prevents inconsistencies through:
1. **Local Decision Timestamps ($s_i$)**:
   Each agent maintains a timestamp vector $s_i \in \mathbb{R}^{M}$. When robot $i$ updates its winning bid $y_{ik}$ or winner $z_{ik}$, it records the current clock time $s_{ik} = t_{	ext{now}}$.
2. **The 18 Consensus Rules**:
   When receiving message $m_j = (y_j, z_j, s_j)$ from neighbor $j$, robot $i$ executes Choi et al.'s 18 decision rules for every task $k$:
   - **Newer Information ($s_{jk} > s_{ik}$)**: If neighbor $j$ has a newer timestamp and bids higher, robot $i$ updates $(y_{ik}, z_{ik}, s_{ik}) \leftarrow (y_{jk}, z_{jk}, s_{jk})$.
   - **Stale Information ($s_{jk} < s_{ik}$)**: Out-of-order or delayed messages from neighbor $j$ are ignored.
   - **Cascade Dropping & Ghost Bid Elimination**: If robot $i$ is outbid on task $k \in b_i$, it drops task $k$ and all subsequent tasks added to bundle $b_i$ after $k$. Crucially, for each dropped task $m$, robot $i$ updates its timestamp $s_{im} = t_{	ext{now}}$. This prevents stale local bids from circulating back as "ghost bids."
3. **Deterministic Tie-Breaking**:
   If two robots bid identical scores $y_{ik} = y_{jk}$ within numerical tolerance ($10^{-5}$), ties are broken deterministically by agent ID ($z_{ik} = \min(i, j)$).
4. **Convergence Invariance**:
   Because the task set is static, utility satisfies DMU, and tie-breaking is strictly total-ordered, the bundle configuration is an invariant fixed point of the 18-rule consensus map. Hence, asynchronous message interleaving affects only convergence duration, **never the final assigned bundles or winners**.
